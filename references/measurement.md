# 口径与归因

- 当前窗口有效上下文、本地累计历史文件、输入 Token 和真实网络字节是不同指标，不能互相换算。压缩可以减少上下文；部分连接续接只发送新增输入，不能假设每轮完整重传旧材料。
- Token 必须分别报告输入、其中的缓存输入、输出、推理子集及记录覆盖。累计计数不等于账号账单或剩余额度。累计窗口与单次请求不可混用。
- 请求有效速率下降是观测结果，不是“模型变笨”的测量。单次高推理请求、排队、网络或服务端策略都可能影响耗时。明确的限速错误应单列，不由压缩次数推断。
- 流量可来自明确选定的系统网卡或可选 Mihomo 本地接口，按来源和计数段分别取差。多个来源不相加；报告采用最新采样来源，必须同时展示 provider 与 scope。切换来源后的首个样本不足以计算差值，保持未知。任一计数回退时划分新段，不产生负流量或跨重启错误差值。
- 系统网卡计数包含使用该接口的所有程序。只选一张接口，不将物理网卡、VPN/TUN、回环、桥接设备的计数相加；同一个数据包可能经过多个接口。Linux 计数属于当前进程的网络命名空间，容器内的接口不等于宿主机网络。系统来源的进程专属字节为 null，不伪造 Codex 的精确消耗。
- Mihomo 来源只覆盖经过该代理内核的数据；绕过该内核的数据不在覆盖范围。兼容客户端可能提供本地命名管道、Unix socket 或回环 HTTP；HTTP 不带凭证、查询参数、不跟随重定向，只请求 /connections。未配置兼容接口时不尝试读取其他软件配置或认证信息。
- Codex/ChatGPT 进程采样覆盖多个会话。连接关闭后的最后一段或完全落在两次采样之间的短连接可能漏记，因此进程流量标为下界，不能当作某个会话的精确上传量。
- 服务商转发 IN/OUT、套餐扣量、物理网卡和代理内核的计量可能不同，需对齐设备、时间、节点与 GB/GiB。新节点不能追溯旧节点的未记录数据。来源 IP 数不等于物理设备数。
- TCP 重传段数不能直接换算额外字节或实际丢包率。不把猜测的每次请求体积乘调用次数作为实测流量。
- 只有实际数据超过配置提醒值或相对基线变化时才报对应数值；缺样本、过期、来源不可达时显示未知。没有校准过的告警值不能证明故障或承诺换对话后的改善幅度。
